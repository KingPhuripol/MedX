## Idea of Project & Background

ปัจจุบันระบบปัญญาประดิษฐ์ทางการแพทย์ส่วนใหญ่ถูกพัฒนาขึ้นเพื่อทำงานเฉพาะด้าน เช่นรองรับโรคใดโรคหนึ่ง ใช้ข้อมูลเพียงบางประเภท หรือมุ่งเน้นงานเฉพาะอย่าง นอกจากนี้ ระบบจำนวนมากยังใช้การประมวลผลผู้ป่วยในรูปแบบเดียวกัน โดยไม่ได้ปรับตามปริมาณหรือประเภทของข้อมูลที่มีอยู่ในแต่ละกรณี

ในสถานการณ์จริงการรับผู้ป่วยที่ด่านหน้าของโรงพยาบาล ข้อมูลสำหรับการตัดสินใจมักยังไม่ครบถ้วนตั้งแต่เริ่มต้น แต่จะค่อย ๆ เพิ่มขึ้นตามลำดับเวลา โดยเริ่มจากอาการและประวัติผู้ป่วย ตามด้วยข้อมูลจากสัญญาณชีพ ผลตรวจทางห้องปฏิบัติการ และภาพทางการแพทย์ ขณะที่ภาพถ่ายทางรังสีและผลการอ่านของแพทย์ผู้เชี่ยวชาญอาจต้องรอหลายชั่วโมง ดังนั้นในแต่ละช่วงเวลาผู้ปฏิบัติงานจึงต้องตัดสินใจจากข้อมูลที่มี ณ ขณะนั้น ไม่ใช่ข้อมูลทั้งหมดที่อาจได้รับในภายหลัง

คำถามสำคัญจึงไม่ได้มีเพียงว่าผู้ป่วยมีแนวโน้มจะเป็นโรคอะไร แต่รวมถึงผู้ป่วยมีความเร่งด่วนในระดับใด ควรซักถามหรือส่งตรวจอะไรเพิ่มเติม และเมื่อใดที่ข้อมูลที่มีอยู่ยังไม่เพียงพอจนควรส่งต่อให้แพทย์เป็นผู้พิจารณา โดยเฉพาะในกรณีฉุกเฉิน ความผิดพลาดที่อาจส่งผลกระทบรุนแรงคือการประเมินความเร่งด่วนต่ำกว่าความเป็นจริง (under-triage) หรือการให้คำแนะนำที่สร้างความมั่นใจมากเกินไป ทั้งที่หลักฐานยังไม่เพียงพอ

จากปัญหาดังกล่าว ผู้จัดทำจึงสนใจพัฒนาโมเดลพื้นฐานแบบมัลติโมดัล (multimodal foundation model) ทางการแพทย์ขนาดประมาณ 27 พันล้านพารามิเตอร์ (27B) แบบเปิดน้ำหนักโมเดล (open-weight) โดยรองรับข้อมูลหลายประเภท ได้แก่ ข้อความทางคลินิก ภาพถ่ายทางการแพทย์สองมิติ ภาพปริมาตรสามมิติจากเครื่อง CT และ MRI ข้อมูลเชิงโครงสร้าง และประวัติผู้ป่วยตามช่วงเวลา

แนวคิดหลักของโมเดลคือ ไม่จำเป็นต้องใช้กระบวนการคำนวณแบบเดียวกันกับผู้ป่วยทุกราย แต่สามารถเลือกและนำเฉพาะข้อมูลที่มีอยู่และเกี่ยวข้องกับผู้ป่วยในขณะนั้นมาประกอบเป็นเส้นทางการคำนวณเฉพาะราย ในรูปแบบกราฟการคำนวณเฉพาะเคสแบบมีชนิดและไม่มีวงจรย้อนกลับ (typed directed acyclic graph) โดยโครงสร้างการคำนวณดังกล่าวสามารถบันทึกไว้เป็นไฟล์และนำกลับมาเล่นซ้ำเพื่อให้ได้ผลลัพธ์เดิม รวมถึงสามารถทดลองตัดหรือสลับส่วนประกอบต่าง ๆ เพื่อประเมินว่าแต่ละส่วนของโครงสร้างมีผลต่อคำตอบจริงหรือไม่ แทนที่จะเป็นเพียงคำอธิบายที่สร้างขึ้นภายหลังจากที่โมเดลให้คำตอบแล้ว

ควบคู่กันนั้น ผู้จัดทำจะพัฒนาระบบ AI Clinical Front Door ซึ่งเป็นระบบสนับสนุนการตัดสินใจที่ออกแบบแบบ API-first คือทุกความสามารถของระบบถูกเปิดให้เรียกใช้ผ่าน API ที่มีสัญญาการเรียกใช้ (contract) ชัดเจน ส่วนหน้าจอผู้ใช้งานเป็นเพียงผู้เรียกใช้ API ชุดเดียวกัน โดยระบบทำหน้าที่ซักประวัติเบื้องต้น คัดกรองภาวะฉุกเฉิน เสนอแนวทางการดูแลให้แพทย์พิจารณา และแนะนำว่าควรเก็บข้อมูลหรือส่งตรวจอะไรเพิ่มเติม รวมถึงแสดงระดับความไม่แน่นอนของผลลัพธ์ และส่งต่อให้บุคลากรทางการแพทย์เมื่อหลักฐานยังไม่เพียงพอ โดยการเรียกใช้โมเดลทั้งหมดจะผ่าน Model Gateway ซึ่งเป็นชั้นกลางที่รวมการเรียกใช้โมเดลไว้ที่จุดเดียว กำหนดรูปแบบข้อมูลเข้าและออกให้คงที่ จึงสามารถเปลี่ยนหรือสลับโมเดลเบื้องหลังได้โดยไม่กระทบระบบส่วนอื่น และกำหนดให้ผลลัพธ์ที่ได้จากระบบต้องผ่านการตรวจสอบและยืนยันโดยมนุษย์ก่อนนำไปใช้ในการตัดสินใจทางคลินิก

## Objective

1. พัฒนาโมเดลมัลติโมดัลทางการแพทย์ขนาดประมาณ 27B ในรูปแบบ open-weight ที่รองรับข้อมูลหลายประเภท ได้แก่ ข้อความทางคลินิก ภาพทางการแพทย์สองมิติ ภาพปริมาตรสามมิติ ข้อมูลเชิงโครงสร้าง และข้อมูลผู้ป่วยตามช่วงเวลา
2. พัฒนา Case Graph Compiler และตัวประมวลผลกราฟแบบมีชนิด (Typed Graph Executor) เพื่อประกอบหลักฐานที่มีอยู่ในแต่ละเคสเป็นกราฟการคำนวณเฉพาะราย ซึ่งสามารถบันทึก นำกลับมาเล่นซ้ำ และตรวจสอบย้อนกลับได้
3. พัฒนาระบบ AI Clinical Front Door ในรูปแบบ API-first เพื่อสนับสนุนการคัดกรองความเร่งด่วน เสนอแนวทางการดูแล แนะนำข้อมูลหรือการตรวจที่ควรเก็บเพิ่มเติม และส่งต่อให้บุคลากรทางการแพทย์เมื่อหลักฐานไม่เพียงพอ โดยผลลัพธ์ทุกขั้นตอนต้องผ่านการยืนยันจากมนุษย์
4. ประเมินประสิทธิภาพของแนวทางที่พัฒนาขึ้นโดยเปรียบเทียบกับวิธีที่ใช้เส้นทางการคำนวณแบบคงที่ ภายใต้งบประมาณด้านข้อมูลและการคำนวณที่ใกล้เคียงกัน เพื่อประเมินผลของการปรับเส้นทางการคำนวณตามแต่ละเคส
5. รักษาความถูกต้องของข้อมูลตามเวลาและระดับผู้ป่วย โดยแบ่งชุดข้อมูลในระดับผู้ป่วยก่อนสร้างตัวอย่างสำหรับการทดลอง และกำหนดให้หลักฐานทุกชิ้นมีระบุเวลาที่ข้อมูลพร้อมใช้งาน เพื่อป้องกันการนำข้อมูลที่ยังไม่เกิดขึ้น ณ เวลาตัดสินใจมาใช้ในการประเมิน

## Scope of work

**การพัฒนาโมเดลมัลติโมดัลขนาดประมาณ 27B:**

พัฒนาส่วน encoder สำหรับข้อมูลแต่ละประเภท ได้แก่ ข้อความทางคลินิก ภาพทางการแพทย์สองมิติ ภาพปริมาตรสามมิติจาก CT และ MRI ข้อมูลเชิงโครงสร้าง และข้อมูลตามลำดับเวลา เพื่อรวมเป็นตัวแทนสถานะ (representation) ของผู้ป่วยรายเดียวกัน โดยเริ่มจากโมเดลขนาดเล็กเพื่อทดสอบสถาปัตยกรรมก่อนขยายสู่ขนาดประมาณ 27B

**การพัฒนากราฟการคำนวณเฉพาะเคส:**

พัฒนา Case Graph Compiler เพื่อเลือกโหนด เส้นเชื่อม ตัวดำเนินการ และเงื่อนไขการหยุดตามหลักฐานของแต่ละเคส พร้อมกลไกบันทึกและเล่นซ้ำกราฟที่ใช้งานจริงเพื่อให้ได้ผลลัพธ์เดิม

**การจัดการข้อมูลและความถูกต้องเชิงเวลา:**

ใช้เฉพาะข้อมูลสาธารณะที่มีใบอนุญาต ข้อมูลสังเคราะห์ หรือข้อมูลที่ได้รับอนุญาตอย่างเป็นทางการ แบ่งชุดข้อมูลในระดับผู้ป่วยก่อนสร้างตัวอย่าง และป้องกันไม่ให้ข้อมูลที่เกิดขึ้นหลังเวลาตัดสินใจรั่วไหลเข้าสู่การเรียนรู้หรือการประเมินผล

**การพัฒนาระบบ AI Clinical Front Door:**

พัฒนาส่วนซักประวัติที่แยกข้อมูลที่ทราบ ไม่ทราบ ปฏิเสธที่จะให้ และยังไม่มีออกจากกัน พร้อมระบบกฎคัดกรองภาวะฉุกเฉินที่ทำงานก่อนโมเดลและไม่สามารถถูกโมเดลลบล้างได้ พัฒนาหน้าจอสรุปผลที่แสดงระดับความเร่งด่วน แนวทางการดูแล ข้อมูลที่ยังขาด และความไม่แน่นอน พร้อมบันทึกเพื่อตรวจสอบย้อนหลัง

**การทดสอบและประเมินผล:**

ประเมินด้วยกรณีศึกษาจำลองที่ครอบคลุมหลายระบบโรค หลายระดับความเร่งด่วน และกรณีข้อมูลขาดหายหรือขัดแย้งกัน โดยเน้นตัวชี้วัดด้านความปลอดภัย เช่น ความไวต่อกรณีวิกฤตและอัตรา under-triage

**การเปรียบเทียบกับวิธีที่มีอยู่:**

เปรียบเทียบกับวิธีที่ใช้เส้นทางการคำนวณคงที่ กราฟโครงสร้างคงที่ และการเลือกเส้นทางแบบสุ่ม โดยควบคุมจำนวนพารามิเตอร์ ปริมาณข้อมูล และงบประมาณการคำนวณให้อยู่ในระดับที่เทียบเคียงกัน พร้อมรายงานผลทั้งที่สนับสนุนและไม่สนับสนุนสมมติฐาน

**ขอบเขตที่ไม่รวมอยู่ในโครงงาน:**

ระบบที่พัฒนาขึ้นเป็นต้นแบบสำหรับการวิจัยและสนับสนุนการตัดสินใจเท่านั้น ไม่ได้มีวัตถุประสงค์เพื่อวินิจฉัยโรค สั่งการรักษา สั่งยา สั่งตรวจ ส่งต่อผู้ป่วย หรือจำหน่ายผู้ป่วยโดยอัตโนมัติ ระบบจะไม่ถูกนำไปใช้กับผู้ป่วยจริง และจะไม่ส่งข้อมูลผู้ป่วยที่สามารถระบุตัวตนได้ออกไปยังบริการภายนอก

## Expected Result

1. **โมเดลแบบ open-weight พร้อมเอกสารกำกับ** — ได้โมเดลมัลติโมดัลทางการแพทย์แบบ open-weight พร้อมเอกสารกำกับที่ระบุขอบเขตของข้อมูลที่ใช้ในการฝึก ข้อจำกัดของโมเดล และเงื่อนไขการนำไปใช้งาน
2. **ความสามารถในการตรวจสอบย้อนกลับของกระบวนการคำนวณ** — ได้กราฟการคำนวณที่ถูกใช้งานจริงในแต่ละเคสในรูปแบบที่สามารถบันทึกและนำกลับมาเล่นซ้ำได้ ทำให้สามารถตรวจสอบได้ว่าระบบใช้หลักฐานใด และผ่านขั้นตอนการคำนวณใดบ้างก่อนสร้างผลลัพธ์
3. **ระบบสนับสนุนการตัดสินใจที่สาธิตกระบวนการได้ครบถ้วน** — ได้ระบบ AI Clinical Front Door ที่สามารถสาธิตกระบวนการตั้งแต่การซักประวัติ การคัดกรองภาวะฉุกเฉิน การเสนอแนวทางการดูแล ไปจนถึงการบันทึกการยืนยันผลโดยผู้ใช้งานที่เป็นมนุษย์ รวมถึงสามารถสลับผู้ให้บริการโมเดลได้โดยไม่ต้องแก้ไขระบบในส่วนของผู้ใช้งาน
4. **หลักฐานเชิงประจักษ์ที่สามารถทำซ้ำได้** — ได้ผลการเปรียบเทียบภายใต้งบประมาณด้านข้อมูลและการคำนวณที่ใกล้เคียงกัน พร้อมชุดคำสั่ง ค่าตั้งต้น และเวอร์ชันของข้อมูลที่ใช้ในการทดลอง เพื่อให้ผู้อื่นสามารถนำไปทำซ้ำได้ โดยรายงานทั้งผลที่สนับสนุนและไม่สนับสนุนสมมติฐานของโครงการ
5. **กลไกที่ช่วยลดความเสี่ยงจากการประเมินความเร่งด่วนต่ำกว่าความเป็นจริง** — ได้ชุดตัวชี้วัดและกลไกการทำงานที่ให้ความสำคัญกับกรณีวิกฤตเป็นลำดับแรก โดยเมื่อหลักฐานไม่เพียงพอ ระบบจะงดการให้ข้อสรุปและส่งต่อให้มนุษย์พิจารณา แทนการให้คำตอบที่มีความมั่นใจสูงทั้งที่ยังไม่มีหลักฐานเพียงพอ
